# Production-readiness audit: Polarion ALM Validation Studio 0.5.0

Audit date: 2026-11-10. Scope: the existing implementation, as requested: no rewrite, no feature removed, architecture unchanged,
existing tests and interfaces preserved. Every fix below was made only after the defect was reproduced, and each has a regression
test that **fails on the old code and passes on the new code**.

## 1. How to read the evidence

| Class | Meaning |
|---|---|
| **Mock** | Passed against the bundled mock Polarion (`mock_polarion/`). Proves the code does what the mock does, nothing more. |
| **Real 2606** | Executed against the real Polarion 2606 on this machine. The login used was the one the user gave in chat for their local trial server. Only **read-only** calls were made. |
| **Partial** | Some paths verified for real, others not. |
| **Not verified** | No evidence beyond reading the code or the documented API. |
| **Blocked** | Cannot be verified without something only the owner can provide (a Personal Access Token, an approved test project, another server). |

A mock passing never moves an item out of "Mock".

## 2. Verification summary

### 2.1 Verified against real Polarion 2606 (read-only)
- Version detection, provider probing, SOAP login with password, project listing (5 projects), 33 capabilities resolved (2 confirmed by a real call, 17 detected from the live WSDL/spec, 7 documented).
- SOAP read of Work Item types (12 = 12 as read from repository files), link roles, custom fields (counts agree with the files), enumerations, documents.
- **SOAP project roles** after fix A3 (before the fix they were silently missing).
- **Effective permission checks** over SOAP `hasPermission`: `admin` granted read/modify/delete/comment, `user1` (project_user) read only, an unknown user nothing.
- Repository configuration read through the local reader (`svnlook`): workflows, fields, enumerations, roles, permissions, 202 templates; 14 of 14 health checks produce results on `drivepilot` and `Vision`, none BLOCKED.
- Script and Velocity analysis of the real templates (no errors).
- Rich Pages listing from the repository after fix A4 (45 and 44 pages).
- The login form in a real headless Edge (field names `j_username`, `j_password`, `form#logInForm`).
- The SOAP fault wording of an expired or missing session (`Not authorized.`) and the `Project.location` format (see A2, A3).
- The read-prefix heuristic for SOAP (`get`, `query`, `has`, `can`, `is`, `find`, `search`, `count`) against the **real WSDL of all five services**: of 279 operations, the only prefix matches that sound like mutations are `can*` permission queries. No read-prefixed operation writes.
- Windows Credential Manager storage of a 3,000-character secret (after fix A5), using a temporary entry that was removed.
- TortoiseSVN is found and `TortoiseMerge`/`TortoiseProc` start with the generated command lines.

### 2.2 Verified against mocks only

## 3. Prioritized defect list

Severity: **High** = wrong or unsafe result likely in real use. **Medium** = wrong result in some environments. **Low** = minor.
Status: all items below marked **Fixed** have a regression test in `tests/test_audit_fixes.py` (or the file named) and pass.

| ID | Sev | Defect | Evidence | Status | Files |
|---|---|---|---|---|---|
| A1 | High (security) | REST paging followed `links.next` to **any** host and sent the bearer token with it. A compromised server or proxy could capture the token. | Reproduced with a recording transport: the token reached `attacker.example`. | **Fixed**: a next link on another origin is ignored; the next page is requested from the configured server by page number. | `src/pavs/polarion/rest/client.py` |
| A2 | High | A SOAP session that timed out on the server was never recovered: later runs showed every health check BLOCKED with a misleading "sign in" remedy until the person reconnected. | Real 2606 answers an expired or missing session with the fault `Not authorized.`; reproduced with the mock by clearing sessions. | **Fixed**: on that fault, and only when `hasSubject` confirms the session is gone, the client signs in again and repeats a **read** once. Writes are never repeated. A real permission denial is not retried. | `src/pavs/polarion/soap/client.py`, `connection.py` |
| A3 | High | Project roles were never read over SOAP on a real server: `Project.location` is the descriptor file `default:/Vision/.polarion/polarion-project.xml`, but `Security.getContextRoles` accepts only the folder `default:/Vision`. SOAP-only users got no project roles. | **Real 2606**: error "Location is not a valid context"; the mock hid it because it returned the folder. | **Fixed**; the mock now behaves like the real server (rejects the file form), and four existing tests fail without the fix. | `src/pavs/engines/inspection/readers_roles.py`, `mock_polarion/app.py` |
| A4 | Medium | SOAP only lists legacy Wiki pages, yet the section reported "complete, 0 pages" for projects holding dozens of Rich Pages / LiveReports. | **Real 2606**: SOAP 0 pages; repository holds 45 in `Vision`. | **Fixed**: pages are listed from the repository when available; with only SOAP the section is marked partial with an explicit gap. | `src/pavs/engines/inspection/readers_documents.py` |
| A5 | Medium | "Remember credentials" failed for long secrets: Windows Credential Manager rejects entries above about 1,250 characters, and a JWT is often longer. | **Real**: 1,000 chars stored, 1,500 failed with `CredWrite 1783`. | **Fixed**: long payloads are split over several entries and reassembled; small payloads are stored exactly as before. Verified round trip in the real store. | `src/pavs/infra/vault.py` |
| A6 | Medium | A server that redirects (typically http to https) was reported as "REST is switched off". | Reproduced. | **Fixed**: the message names the redirect target and asks the person to use it. Credentials are still never sent to a redirect target. | `src/pavs/polarion/connection.py` |
| A7 | Medium | Connecting from the Connect page rebuilt the TLS settings from the checkbox alone, silently **dropping a corporate CA bundle** saved in the environment dialog. | Code reading plus reproduction. | **Fixed**. | `src/pavs/services/connections.py` |
| B1 | High | Requirement "Everyone **except** X can delete Work Items" produced the check "X **can** delete": the opposite of the requirement. | Reproduced. | **Fixed**: reported as not automatable with the reason. | `src/pavs/engines/requirements/rules.py` |
| B2 | High | "The approver can **neither** modify **nor** delete" produced two GRANTED checks. | Reproduced. | **Fixed**: now two DENIED checks. | same |
| B3 | High | "Only X can delete" kept the positive check and dropped the exclusivity, so it could pass while every other role also had the right. | Reproduced. | **Fixed**: the positive check is kept and a finding states that the exclusive part is untested. | same |
| B4 | Medium | "The role X must not exist" became the positive check for a role named "X must not". | Reproduced. | **Fixed**: an absence check with the correct name. | same |
| B5 | Medium | "can read and comment **on** Work Items" treated "comment" as the object, so read/modify were checked on **Comment**. | Reproduced. | **Fixed**. | same |
| B6 | Medium | "Approval **requires** two reviewers" was silently dropped (no check, no finding). | Reproduced. | **Fixed**: reported as not automatable. | same |
| B7 | Medium | "Defects can be reopened **from Closed to Open**" became a permission to "open" Work Items. | Reproduced. | **Fixed**. | same |
| B8 | Medium | "…with the role verifies" produced the link role "the". | Reproduced. | **Fixed**. | same |
| B9 | Medium | "The role X cannot ..." gave the role "The" when the role list was unknown; Markdown bullet lists lost every item after the first; headings polluted the requirement. | Reproduced (found by the end-to-end run). | **Fixed** earlier the same day; tests in `tests/test_requirements.py`. | `rules.py`, `importers.py` |
| C1 | Medium | The enumeration health check reported 37 false duplicates: SOAP `getAllEnumOptionsForId` returns every type's variant merged. | **Real 2606**. | **Fixed** earlier; test in `tests/test_testing_engine.py`. | `readers`/`health.py` |
| C2 | Medium | Roles defined by the project itself (`<project>/.polarion/security/project-roles.xml`) were ignored, giving a false "role not defined" finding. | **Real 2606** (`Vision`, role `system_Engineer`). | **Fixed** earlier; test in `tests/test_inspection.py`. | `readers_roles.py` |
| C3 | Medium | The local-repository fallback applied to any server on `127.0.0.1`, including a mock or tunnel on another port. | Reproduced by the end-to-end run. | **Fixed** earlier: automatic only on a normal port. | `connection.py` |

## 5. Security findings

| Area | Result | Notes |
|---|---|---|
| Write Guard | **Sound** | Read-only by default; a write needs an authorization issued by that guard, for the environment, an approved test project, not expired, and (production) the typed name. Verified by tests and end-to-end: unapproved runs made no write request. The SOAP read/write classification was checked against the real WSDL (no read-prefixed operation mutates). |
| Token handling | **Fixed A1** | The bearer token could be sent to a host named in `links.next`. Redirects are never followed. |
| Credential storage | **Fixed A5** | Windows Credential Manager (DPAPI per user). Nothing sensitive in the database. Long secrets now stored in pieces. The repository password and the test-account tokens are covered too. |
| Secret redaction | **Sound** | Structural redaction of `password`, `token`, `sessionID` elements, JSON fields, Bearer/Basic, key=value, plus the registry of known secrets (so a short password in a SOAP body is still removed). Verified end to end across the database, logs, audit log and all four export formats; spreadsheet cells cannot start a formula. |
| Untrusted XML | **Sound** | Any DOCTYPE/ENTITY is refused before parsing (`infra/safexml.py`). |
| Production restrictions | **Sound** | Typed environment name for writes; checkout/merge hand-offs need the Admin role; deleting an environment needs Admin. |
| Test-data cleanup | **Sound** | Items are tagged `[PAVS-<run>]`, recorded before use, capped at 30 per run, deleted in a `finally` block, and only deleted if the tag is still present. Verified on the mock for all profiles; **not on a real server**. |
| Audit logging | **Adequate** | Connections, credential changes, inspections, test runs, behavioural start/cleanup, write authorize/blocked, exports, role changes and denials, history clearing, merge compare and TortoiseSVN hand-offs are recorded. See O4/O5. |
| Report exports | **Sound** | Scrubbed; reports contain the Windows user name and server URL by design ("Run by", "Server"). |
| Dependencies | **Clean** | `pip-audit` reports no known vulnerabilities. |
| Roles | **Guardrail only** | A desktop-tool role, not a security boundary against someone with file access (documented). |

## 6. Regression results (this audit)
- Automated suite: **267 tests, all pass** (243 before the audit; 24 added in `tests/test_audit_fixes.py`).
- End-to-end: **47 scenarios, all pass** (`qa check --real-local --exe ...`): five release profiles over real HTTP, failure cases, requirement formats, production safety, roles, history, merge, exports, secrets scan, GUI pages, CLI and executables, single-window behaviour, browser checks, and the real local server without a login.
- Fix proofs: the five tests protecting A1/A2 fail on the pre-audit code (verified by stashing the fix); four existing inspection tests fail on the pre-audit code against the stricter mock (A3).
- `pip-audit`: no known vulnerabilities.

## 7. Recommended fixes and implementation plan (preserving the architecture)

All defects with a clear fix are already implemented. Remaining work, in order:
1. **Verify REST on a real server** (O1): create a PAT, run the read-only checks, record the results in `docs/COMPATIBILITY.md` "Verified" column. No code change expected; fix whatever the first real REST response shows (the same way A3 was found).
2. **Run the behavioural tests once on an approved test project** (O2), inspect the audit log and the project for leftovers. This is the only way to confirm the write-path assumptions in `docs/ROADMAP.md`.
3. **Verify 2410, 2506 and 2512** when servers are available, in particular 2410 with REST off (SOAP only), using the real-server procedure in `docs/TESTING-GUIDE.md` section 9.
4. Add proxy fields to the environment dialog if an enterprise deployment needs them (O3).
5. Optional: H15 (workflow condition parameters, O6), a hash chain for the audit log (O4), one audit line per write (O5).
